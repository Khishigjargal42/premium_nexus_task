# Өгөгдлийн шинжээчийн даалгавар — Эцсийн хувилбар

## 1. Төслийн зорилго

Өгөгдсөн борлуулалт, хэрэглэгч, бүтээгдэхүүн, салбар, inventory болон survey мэдээлэлд шинжилгээ хийж, бизнесийн гол асуудал болон боломжийг тодорхойлон хэрэгжүүлэх боломжтой санал боловсруулах.

Даалгаврын үндсэн шаардлага нь зөвхөн өгөгдсөн өгөгдлийг ашиглах бөгөөд хүлээгдэж буй үр дүн нь:
- Шинжилгээний танилцуулга
- Түлхүүр insight
- Хэрэгжүүлэх боломжтой санал

## 3. Шинжилгээний дараалал

1. Өгөгдлийн бүтэц болон чанарыг шалгасан.
2. Missing value, duplicate, key duplicate, numeric validity болон referential integrity шалгасан.
3. Sales ба Sales Line-ийн тооцооллын нийцлийг шалгасан.
4. Date багануудыг datetime төрөлд хөрвүүлсэн.
5. Цэвэрлэсэн өгөгдлийг `data/cleaned/` дотор хадгалсан.
6. Борлуулалт, салбар, хэрэглэгч, бүтээгдэхүүн, inventory болон survey түвшинд EDA хийсэн.
7. Ололтуудыг бизнесийн санал зөвлөмж болгон нэгтгэсэн.

## 5. Гол санал зөвлөмж

### 1. Өндөр үнэ цэнтэй бүтээгдэхүүний нөөцийн хяналт
Pasta Box, Cheesecake Slice, Beef Onigiri зэрэг өндөр орлоготой бөгөөд LOW/OOS төлөв харьцангуй өндөр бүтээгдэхүүнийг тэргүүлэх хяналтын бүлэгт оруулах.

### 2. Давтан худалдан авалтыг хадгалах
Morning commuter болон Healthy routine зэрэг өндөр хэрэглэгчийн үнэ цэнтэй сегментүүдэд loyalty болон персоналчилсан санал турших.

### 3. Бүтээгдэхүүний чанарыг сайжруулах
Харьцангуй бага чанарын оноотой Iced Coffee, Protein Bar, Chicken Sandwich зэрэг бүтээгдэхүүнийг review хийх.

### 4. Бүтээгдэхүүний багцыг оновчлох
ReadyToEat ангиллын бэлэн байдлыг хамгаалж, Beverage дээр cross-sell болон bundle турших.

## 6. Хязгаарлалт

- `customer_id` нь 856 transaction дээр missing тул customer-level analysis нь зөвхөн ID тодорхой transaction-уудыг ашигласан.
- Inventory `stock_flag`-ийн deterministic дүрэм өгөгдлөөс баталгаажаагүй тул эх өгөгдлийн утгыг өөрчлөөгүй.
- Stockout-оос үүссэн бодит lost sales-ийг шууд тооцоолох мэдээлэл байхгүй.
- Survey-ийн quality score болон repurchase intent-ийн хамаарлыг causal relationship гэж тайлбарлаагүй.
